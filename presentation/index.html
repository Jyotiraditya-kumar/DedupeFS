Problem Formulation

The Storage Proliferation Crisis & I/O Bottleneck

Why Naive Approaches Fail

1. Exponential Data Redundancy:

Studies demonstrate 30% to 75% of capacity in VM clusters, codebases, and backup shares consists of identical files.

2. Pairwise Comparison is O(N²):

For 500,000 files, N(N-1)/2 requires ~1.25 × 10¹¹ comparisons, rendering it computationally impossible.

3. Naive Cryptographic Hashing is I/O Bound:

Computing full SHA-256 for all files reads gigabytes/terabytes of disk data just to discover 80% are unique!

The DedupFS Solution

1. Multi-Tier Pruning Hierarchy:

Tier 1 eliminates unique files in O(1) time with 0 disk reads. Tier 2 discards header mismatches with a 4KB prefix test.

2. Probabilistic In-Memory Filtering:

Bloom Filter with Kirsch-Mitzenmacher double-hashing rejects ~99% of unique files in O(k) bit tests (Zero FN guaranteed).

3. Zero Data Loss Guarantee:

64KB binary memcmp byte verifier guarantees 0% collision risk. POSIX atomic hard linking consolidates physical blocks safely.

Architecture

DedupFS 6-Stage Multi-Tier Pipeline

STAGE 1 • SCANNER
POSIX Recursive Scan

Recursive filesystem traversal using stat(2). Tracks 64-bit (st_dev, st_ino) keys to prevent cyclic traversals and skip existing hard links.

STAGE 2 • TIER 1
O(1) Size Bucketing

Files with unique byte lengths cannot have duplicates. Discarded in O(1) time without reading a single byte from storage (~25% pruned).

STAGE 3 • TIER 2
4KB Murmur3 Prefix

Reads only the first 4,096 bytes and computes 128-bit MurmurHash3. Mismatched file headers are rejected without reading file bodies.

STAGE 4 • TIER 3
Streaming Full SHA-256

Only surviving candidates undergo full 256-bit cryptographic digest generation using OpenSSL hardware-accelerated EVP streaming.

STAGE 5 • INDEXING
Bloom Filter + Hash Table

O(k) bit tests in dynamic Bloom filter filter out unique files. Primary chained hash table indexes candidates with automatic rehashing (λ ≤ 0.75).

STAGE 6 • CONSOLIDATION
Verifier + Atomic Links

64KB binary memcmp byte verifier confirms exact content. POSIX atomic link(2) + rename(2) consolidates inodes and frees physical blocks.

Core Data Structure 1

Optimal Dynamic Bloom Filter: Mathematics & Invariants

Mathematical Optimization

Optimal Bits: m = - (n • ln p) / (ln 2)²
Optimal Hashes: k = (m / n) • ln 2

Kirsch-Mitzenmacher Double-Hashing: Simulates k uniform hash functions from two 64-bit words of the SHA-256 digest:

g_i(x) = (h1(x) + i • h2(x)) mod m

Zero False Negatives Invariant (FN = 0): If any bit is 0, the key was mathematically never inserted. True negatives bypass table lookup in O(k) bit operations!

Primary Chained Inverted Hash Table: Dynamic Rehashing

Inverted Index Architecture

Maps 256-bit cryptographic fingerprints to clusters of FileInfo metadata (inode, path, size, link count).

Collision Resolution: Separate chaining with linked lists of key-value nodes.

Equivalence Classes: Extracts clusters with file count ≥ 2 into verified duplicate groups.

Data Safety

Streaming Byte Verifier & Atomic POSIX Consolidation

64KB Streaming Byte Verifier

Even though SHA-256 collision probability is 2⁻²⁵⁶, enterprise systems require absolute mathematical certainty.

• Reads files in two 64KB aligned buffers and performs raw binary memcmp.
• Catches 1-byte EOF differences where prefix and size match.
• Confirmed 3,092 byte-by-byte matches with zero collisions.

Atomic Hard-Link Consolidation

Frees redundant disk blocks while preserving filenames, paths, and permissions.

1. link(canonical_path, temp_path)
2. rename(temp_path, duplicate_path)

• Crash-safe: duplicate is never missing during failure.
• Kernel reclaims blocks; st_nlink increments on unified inode.

Validation Methodology

Dual-Folder Architecture: Ground Truth vs. Active Workspace

📁 ground_truth/ (Untouched Reference)

Contains the original un-deduplicated files with independent physical inodes (st_nlink = 1). Never modified by DedupFS.

📁 work/ (Active Workspace)

DedupFS scans and optimizes this directory, unifying inodes into hard links (st_nlink > 1) and reclaiming physical disk blocks.

Automated Verification (--verify): Exhaustively compares every file in work/ against ground_truth/ bit-for-bit to prove 100% byte equivalence and inspect inode link consolidation.
Instant Rollback (--reset): Restores work/ to pristine pre-deduplication state from ground_truth/ in <1 second.
